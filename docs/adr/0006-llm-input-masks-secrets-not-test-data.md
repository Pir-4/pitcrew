# LLM input: secrets masked, stage test data sent as is

Every prompt the Agent gets passes through the same masking as the log lines: the secrets
Pitcrew knows (read through `Settings` or registered with `mask_secrets`) become `***`. Test
data in it (addresses, ids, emails, amounts from a failed test's error or an API answer) is not
masked. The original ground rule also listed customer data and wallet addresses; we narrowed it
because Pitcrew runs only against stage, whose data is generated by the tests and holds no
customer data, and the models are reached only through the internal LiteLLM on AWS Bedrock, in
the company's own AWS account. Masking the data would hide exactly what a fix needs (the value
a pydantic model rejected), and putting it back in the Agent's answers and MRs would be a
second system with its own bugs. A secret, on the other hand, the model must never see: it
could write it into an MR or a Slack post.

## Consequences

- Revisit when Pitcrew reads anything but stage data, or when the security review asks for more.
- A tool that brings external data into the Agent's context (e.g. an Allure MCP server) gets
  the same secret masking before it is given to the Agent.
